# サポートセンターわかくさ サイトレビュー（2026-09-10）

対象: `index.html`（HEAD `4023730`、作業ツリーはクリーン）、`thanks.html`
方法: サブエージェント5体（PC幅ビジュアル / モバイルUX / アクセシビリティ / 情報設計・コピー / 実装品質・SEO）による並列レビュー。
親エージェント側で、影響の大きい指摘は実ファイル・実測で裏取りした。

**このレビューでファイルの変更は行っていない。**

## 検証方法についての注意（重要）

最初に用意したスマホ用スクリーンショットは**誤りだった**。macOS の Chrome はウィンドウ幅に下限（約500px）があり、
`--window-size=390` を指定しても実際のレイアウトは約485〜500pxで組まれる。その左390pxを切り出していたため、
右端が欠けた画像になっていた。これは**サイトの不具合ではなく撮影方法の不具合**。

- 対処: 390px の iframe に読み込む方式で撮り直した（`m-01`〜`m-15`）。
- 影響: モバイルUXエージェントと情報設計エージェントは、いずれも独自にこの不備を検出し、自前で撮り直したうえで判断している。
- 教訓: 今後スマホ表示を確認するときは、iframe 方式か CDP のデバイスエミュレーションを使う。単純な `--window-size` は使えない。

なお iframe 方式にも限界があり、**モバイルブラウザ特有のビューポート挙動は再現しない**（後述 A-1 の症状は iframe では出ない）。

## 優先度A：公開中のサイトで実害が出ている（最優先）

### A-1. 装飾円1つが原因で横180pxはみ出し、スマホ固定CTAの3つ目が画面外に出るおそれ

- 箇所: `index.html:425-434` `.hero::after`（`right: -180px; width: 480px`）、`index.html:417` `.hero { overflow: visible }`、`index.html:67` `body { overflow-x: hidden }`
- 事実: 全幅で `scrollWidth = clientWidth + 180`。これは**3者が独立に同じ値を測っている**（PC幅エージェント、モバイルUXエージェント、親エージェント）。
- 事実: モバイルエミュレーション（390px指定）で `innerWidth` が **570**（= 390 + 180）、375px指定で **555**（= 375 + 180）。
  親エージェントも同じ値を得ている。
- モバイルUXエージェントの実測: `.mobile-action-bar` が幅570pxになり、3つ目の「採用応募」が x=381..558 と画面外。
  `body { overflow-x: hidden }` のため横スクロールで到達もできない。
- **未検証**: 実機 iOS Safari で同じになるかは確認できていない。エージェント自身も推測と明記している。
- なぜ重い: サイトの2大目的のうち「採用」の常時表示CTAが消えうる。`overflow-x: hidden` は症状を隠しているだけ。
- 対応: `.hero { overflow: clip }` を追加し `right: -180px` を `-10%` 程度に。その上で `body { overflow-x: hidden }` を**外し**、
  全幅で `scrollWidth === clientWidth` になることを確認する。

### A-2. 採用セクションの画像が高さ1024px固定で描画される

- 箇所: `index.html:1007-1013` `.recruit-visual img`、`index.html:2467` `<img ... height="1024">`
- 事実: `aspect-ratio: 1.2` を指定しているが、`height` を CSS で指定していないため、HTML の `height="1024"`
  （プレゼンテーション属性）が採用され `aspect-ratio` が無効化される。computed height = `1024px` を実測確認。
- 比較: `.hero-photo` / `.service-image img` / `.job-photo img` はいずれも `height: 100%` を持つ。**ここだけ抜けている**。
- 影響: PCでは右カラムが1024pxになり、左カラム下に約400〜600pxの空の濃緑地が生まれる（`d-05`）。
  スマホでは350×1024に切られ、**2人とも顔が切れてテーブルと足元だけ**になる（`m-08`）。求人カードまでのスクロールが約730px増える。
- 対応: `.recruit-visual img { height: auto; }` を追加。`object-position: center 30%` で人物を残す。
- 補足: 3体（PC幅・モバイル・アクセシビリティ）が独立に指摘。原因分析はPC幅・モバイル両エージェントが `height` 属性、
  アクセシビリティエージェントが `picture { height: 100% }` の百分率解決と分析しており、**原因の説明は割れている**。
  どちらにせよ `height: auto` で解消する。

### A-3. 文字サイズ200%でレイアウトが破綻する（WCAG 1.4.4 / 1.4.10）

親エージェントが 390px の真のレイアウトで等倍と200%を撮り比べ、**等倍では崩れず200%でのみ崩れる**ことを確認した。

- ヘッダーのサイト名がハンバーガーボタンと重なる。`index.html:204` `.brand-copy strong { white-space: nowrap }`。
  実測で `.brand-copy strong` の右端が419px（390px幅を29pxオーバー）。**メニューを開けなくなる**。
- アクセス情報カードが右端で切れ、**住所末尾・メールアドレス・受付時間が読めない**。実測で右端456px（66pxオーバー）。
  原因は `wakakusa2002@gmail.com` が分割不能で `dd` の最小内容幅が406pxになること。
- 下部固定バーの実高が102pxになるのに `body { padding-bottom }` は76px固定（`index.html:1772` `--bar-space`）。
  差の26px分の本文が永久に隠れる。
- 「地域とともに一歩ずつ」バッジの文字が丸から溢れる。採用の黄色いふきだしが写真をほぼ覆う。
- 対応: `white-space: normal` ＋ `.header-inner { flex-wrap: wrap }` / `.info-item { grid-template-columns: minmax(2.6em, auto) 1fr }`
  ＋ `dd { overflow-wrap: anywhere }` / `--bar-space` を em 基準か `ResizeObserver` で実測に連動させる。

### A-4. 送信後に「戻る」でフォームが再送信不能になる

- 箇所: `index.html:2731-2738`
- 事実: submit時に `button.disabled = true` とラベル変更を行うが、解除する処理がない。`pageshow` ハンドラは存在しない（確認済み）。
- 影響: Formspree が `thanks.html` へリダイレクトした後にブラウザバックすると、bfcache がDOMを復元するため
  **ボタンが「送信しています…」のまま無効**になる。入力し直しても送信できない。送信失敗時も同様。
- 対応: `window.addEventListener('pageshow', function(e){ if(!e.persisted) return; /* ボタン復帰 */ })`
- 補足: 実装品質・アクセシビリティ・情報設計の**3体が独立に指摘**。

### A-5. フォーカスリングが濃緑の上でほぼ見えない（WCAG 2.4.7 / 1.4.11）

- 箇所: `index.html:43` `--focus: #28543b`、`103-110行` `outline: 3px solid var(--focus); outline-offset: 3px`
- 計算値（親エージェントが独立に再計算し、**全数値一致**）:
  - 対 `--leaf-deep #173d2a` = **1.39:1**（基準3:1、不適合）
  - 対 `--leaf-dark #28543b` = **1.00:1**（完全に不可視）
- 該当: 目的別メニュー3本、採用CTA2本、topbar電話、`.contact-phone`、フッターリンク6本ほか計16要素。
  デスクトップで到達可能な約41要素のうち16。
- 対応（最小変更）: 濃緑面のブロックで `--focus: #f3b75f` に切り替える（対 #173d2a = **6.76:1**、対 #28543b = **4.85:1**。親エージェント確認済み）。

### A-6. 入力欄の枠線が見えない（WCAG 1.4.11）

- 箇所: `index.html:1458` `border: 1px solid var(--line)`（`--line: #dce6dc`、背景 `#fcfdf9`）
- 計算値: **1.25:1**（白カード上でも1.28:1、基準3:1）。親エージェント再計算で一致。
- 同じ問題: `index.html:375` `.nav-toggle` の枠（対白 1.28:1）。これは操作部品なので明確に対象。
- 対応: 装飾用 `--line` は残し、操作部品だけ `--line-control: #6b7c72`（対 #fcfdf9 = 4.33:1）を新設して適用。

### A-7. CSS詳細度の衝突で装飾が3か所壊れている

「クラス+タグ」が「クラス単独」に勝つため、意図した指定が打ち消されている。

- `index.html:263` `.header-contact span`（0,1,1）が `index.html:277` `.phone-icon`（0,1,0）に勝つ。
  → 34pxの丸の中で ☎ が中央に来ず、色とサイズも上書きされる。**1061px以上でのみ表示される領域**なので、スマホ確認では気づけない。
- `index.html:827` `.service-note span` が `.service-note-mark` と `.link-arrow` に勝つ。
  → 「＋」丸マークと「→」丸矢印の `place-items: center` が潰れる。
- `index.html:2102` `.footer-bottom span`（640px以下）が `index.html:2648` の入れ子 `<span id="current-year">` にも当たる。
  → スマホで「©」「2026」「サポートセンターわかくさ」が**3行に分断**される。
- 対応: それぞれ `.header-contact a span` / `.service-note > span > span` / `.footer-bottom > span` に限定する。
- 補足: フッターの件は実装品質・情報設計・モバイルUXの**3体が独立に指摘**。

## 優先度C：デザインの体系・品質

### タイポグラフィ
- 実使用フォントサイズが約40種類あり、うち33種が1.1rem未満に `.79 / .80 / .81 / .82 / .83 / .84 / .86rem` と0.01rem刻みで密集。

- 本文まわりに9.9〜11pxの文字が多数。`.stat span` はスマホで `.62rem` = **9.92px**（実測確認）。
  主読者に高齢の家族を含む以上、本文系の下限は14px（`0.875rem`）に統一すべき。

### 配色・トークン

- パレット外の孤立色: `index.html:461` `rgba(217,109,90,.12)` は `--coral`（#9a4034）とは別の色。`index.html:1460` `#fcfdf9` も未変数化。

## 優先度D：実装・パフォーマンス・SEO

### 画像（最大の改善余地）
